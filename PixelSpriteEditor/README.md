# PixelSpriteEditor（Java版）

90年代の対戦格闘ゲーム（ストリートファイターII風）のキャラクタースプライトを
描くためのドット絵エディタです。**Java標準ライブラリ（Swing）のみ**で実装されており、
外部ライブラリ・ビルドツール（Gradle/Maven）は一切使用していません。

このフォルダの中身は**すべてコンパイル前の`.java`ソースコード**です。ビルド済みの
実行ファイルは含まれていません。お使いのWindows PC上で `javac` を使って自分で
コンパイルし、`java` コマンドで実行してください。

> なぜこの形で渡すのか：
> このプロジェクトは元々C++、その後C#で実装していましたが、いずれも
> ビルド済みバイナリをそのまま配布する形式でした。今回は「実行するものを
> 全部自分の手元でソースからビルドする」という、最も確実に信頼できる形を
> 優先し、Java + Swing + JDK標準機能のみで作り直しています。経緯の詳細は
> リポジトリ直下の `README.md` を参照してください。

## 動作環境

- Windows 10/11（Linux/macOSでも動作します）
- JDK（Java Development Kit）がインストールされていること
  - `javac` と `java` コマンドが使えれば十分です
  - **JDK 11以降**で動作します（言語機能をJava 11相当に抑えているため、比較的古い
    JDKでも問題ありません）。[Adoptium Temurin](https://adoptium.net/) などから
    入手できます
- 追加ライブラリのインストールは不要です

## コンパイル方法

PowerShellまたはコマンドプロンプトで `src` フォルダに移動し、以下を実行してください。

```powershell
cd PixelSpriteEditor\src
javac -encoding UTF-8 *.java
```

`-encoding UTF-8` を必ず指定してください。このソースコードはUTF-8で保存されており、
日本語の文字列リテラルを含みます。Windows環境（特に日本語以外のロケール）では
`javac` のデフォルトの文字コードがUTF-8と異なる場合があり、指定を省略すると
コンパイルエラーや文字化けの原因になります。

エラーなく完了すると、`src` フォルダの中に `*.class` ファイルが生成されます。

## 実行方法

```powershell
java Main
```

同じ `src` フォルダの中で実行してください（コンパイルで生成した `.class` ファイルを
そのまま使います）。ウィンドウが立ち上がればOKです。

### 動作確認用の自己テスト（任意）

GUIを使わずにロジック層（Undo/Redo、各ツール、PNG入出力など）だけを検証する
簡易セルフテストも同梱しています。ビルドが正しくできているかの確認に使えます。

```powershell
java SelfTest
```

`SELFTEST: ALL PASSED` と表示されれば正常です。

## 使い方

| 操作 | 内容 |
|---|---|
| 左クリック（鉛筆/消しゴム） | ドラッグで連続描画（間の座標も自動補間） |
| 左クリック（塗りつぶし） | クリックした位置と同じ色の4方向連結領域を塗る |
| 左クリック（スポイト） | クリックした位置の色を現在色にする |
| 左クリック（直線） | 押した位置から離した位置まで直線を描画（ドラッグ中はプレビューのみ、実際のピクセルはマウスを離すまで確定しません） |
| 左クリック（選択） | ドラッグで矩形選択（コピー/切り取り/削除/反転の対象範囲になります） |
| Ctrl+マウスホイール | ズームイン・アウト（カーソル位置を中心に、マウスホイール単体では反応しません） |
| 中ボタンドラッグ / Space+ドラッグ | キャンバスをパン（平行移動） |

キャンバス上にカーソルを合わせると、今どのピクセルの上にいるかが黒白の二重枠で
ハイライトされ、ステータスバー左下にも座標が表示されます。

見た目はJDK標準のSwing「Metal」ルック＆フィールに独自のダークカラーテーマを
適用しており（外部ライブラリ不要）、以前のC++/C#版に近い暗い配色になっています。

### 新規キャンバス

`File > 新規` からピクセル単位で幅・高さを指定して新規作成できます。16の倍数
（例: 64x64）が格ゲー用スプライトのタイル構成に適しています。

### 色

左側のパネルでR/G/B/Aを0-255のスライダー、またはその右の数値欄への直接入力
（キー入力後、Tabやクリックで他の場所にフォーカスを移すと確定）で指定します。
透明色もAスライダーで扱えます（A=0で完全透明）。プレビュー欄はチェッカーボードの
上に現在の色を重ねて表示するので、半透明・透明の見え方も確認できます。

#### パレット

スライダーの下は「パレット」セクションです。ドロップダウンで切り替える固定の
「デフォルト」パレット（15色+透明、編集不可）に加えて、自分だけのパレットを
作成できます。

- **+新規**: パレット名を入力して空のパレットを作成（自動的に選択されます）
- **現在の色をパレットに追加**: 選択中のパレットに今の色を登録（デフォルト
  パレット選択中は無効）
- パレット内の色を**右クリック**すると削除できます（デフォルトパレットの色は
  削除できません）
- **削除**: 選択中のパレットそのものを削除します（デフォルトパレットは削除不可）

自分で作成したパレットは、後述の「プロジェクトを保存」でプロジェクトファイルに
一緒に保存され、次回「プロジェクトを開く」で復元されます（PNG1枚だけの保存/
読み込みでは保存されません）。デフォルトパレットは常に自動的に存在します。

#### 最近使った色

パレットの下の「最近使った色」には、実際に使った色が新しい順に自動で並びます。
クリックでその色を選択、**右クリック**でその項目を一覧から削除できます。

### レイヤー

右側の「レイヤー」パネルで、アクティブなフレーム内のレイヤーを管理します。
一番上のレイヤーがキャンバス上で一番手前に描画されます（パネルのリストも
一番上が最前面のレイヤーです）。

- 行をクリック: そのレイヤーを描画対象（アクティブレイヤー）にする
- チェックボックス: 表示/非表示を切り替え（非表示のレイヤーは合成結果や
  PNG書き出しに含まれません）
- **+追加**: 空のレイヤーを一番上に追加
- **複製**: 選択中のレイヤーを複製
- **削除**: 選択中のレイヤーを削除（レイヤーが1枚だけの場合は無効）
- **↑ / ↓**: レイヤーの重ね順を変更

Undo/Redo（Ctrl+Z/Ctrl+Y）は**レイヤーごとに独立**しています。あるレイヤーで
描いた内容のUndoは、そのレイヤーをアクティブにしているときだけ効きます。
ただし「レイヤーの追加・削除」自体はUndo対象外です（誤って削除した場合、
元に戻す方法はありません）。

### アニメーションフレーム

キャンバス下の「フレーム」パネルでコマ（フレーム）を管理します。各フレームは
独自のレイヤー構成を持ちます。

- サムネイルをクリック: そのフレームを表示/編集対象にする
- **+追加**: 空のフレームを追加
- **複製**: 選択中のフレーム（レイヤー構成ごと）を複製
- **削除**: 選択中のフレームを削除（フレームが1枚だけの場合は無効）
- **← / →**: フレームの並び順を変更
- **▶ 再生 / ■ 停止**: フレームを一定間隔（8fps）で自動的に切り替えて
  簡易プレビュー再生（あくまで確認用で、書き出しには影響しません）
- **オニオンスキン**: 有効にすると、ひとつ前のフレームの内容を半透明で
  重ねて表示し、動きの連続性を確認しやすくします（一つ前のフレームのみ、
  実際のピクセルには影響しません）

フレームの追加・削除もUndo対象外です。

### 選択範囲・コピー＆ペースト・左右反転

ツールバーの「選択」で矩形選択ができます。選択範囲があるときは:

- **編集 > コピー**（Ctrl+C）: 選択範囲をクリップボードにコピー
- **編集 > 切り取り**（Ctrl+X）: コピーしてから選択範囲を透明で塗りつぶす
- **編集 > 選択範囲を削除**（Delete）: 選択範囲を透明で塗りつぶす
- **編集 > 左右反転 / 上下反転**: 選択範囲内だけを反転（選択範囲がない
  ときはアクティブレイヤー全体を反転）

**編集 > 貼り付け**（Ctrl+V）でクリップボードの内容がカーソルに追従する
半透明のプレビューとして現れます。好きな位置でクリックすると確定（1回の
Undo単位）、Escキーでキャンセルできます。コピー＆ペーストとUndo/Redoは、
通常の描画と同じくレイヤー単位で動作します。

### スプライトシート書き出し

`File > スプライトシートとして書き出し...` で、全フレームを1枚のPNGに
並べて書き出せます。列数を指定でき、フレーム数を列数で割った行数で
自動的にグリッド状に配置されます（各セルのサイズはキャンバスの実解像度）。

### プロジェクトの保存/読み込み

PNG1枚だけの保存では、フレーム・レイヤー構成やユーザー作成パレットは
失われます。これらをすべて保持したい場合は `File > プロジェクトを保存` /
`名前を付けてプロジェクトを保存...` で `.pxproj` ファイルとして保存し、
`File > プロジェクトを開く...` で読み込んでください。

`.pxproj` は中身がただのZIPファイルです（`java.util.zip` のみ使用、外部
ライブラリなし）。レイヤーごとに1枚のPNG画像＋構成情報（フレーム数、
レイヤー名・表示状態、ユーザー作成パレット）を記録した
`manifest.properties` が入っているだけなので、`.zip` に拡張子を変えれば
中身を直接確認することもできます。

### PNGの保存について

`File > 保存` / `名前を付けて保存` は**アクティブなフレームの合成結果**
（表示されている見た目そのまま、全レイヤーを合成した1枚）を、キャンバスの
実解像度（表示ズーム倍率とは無関係）でPNGとして書き出します。グリッドや
16x16ガイド、チェッカーボード、選択範囲の枠などの編集用UIは一切含まれません。
`java.awt.image.BufferedImage` と `javax.imageio.ImageIO` のみを使用しており、
透明ピクセルは `alpha = 0` のまま正しく保存されます。

複数フレーム/複数レイヤーの構成をまるごと残したい場合は、PNG書き出しではなく
上記の「プロジェクトの保存」を使ってください。

│  ├─ EditorWindow.java      JFrame。メニュー・ツールバー・レイアウト組み立て、
│  │                          ファイル操作(New/Open/Save/プロジェクト/スプライト
│  │                          シート書き出し)、ショートカット
│  ├─ CanvasPanel.java       アクティブフレームの合成結果を描画（ニアレストネイバー

│  │                          オニオンスキン切り替え
│  ├─ NewCanvasDialog.java   新規キャンバスサイズ指定ダイアログ
│  ├─ EditorState.java       アプリの中心状態（フレーム/レイヤー・ツール・カメラ・
│  │                          色・選択範囲/クリップボード・表示フラグ）
│  ├─ Frame.java             1コマ分＝レイヤーのスタックと合成(composite)

│  ├─ History.java           ストローク単位のUndo/Redo（レイヤーごとに1つ）

│  │                          によるZIP、外部ライブラリ不要）
│  ├─ Tool.java              各ツール共通インターフェース
│  ├─ PencilTool.java        鉛筆（ドラッグ中は線分補間で連続描画）
│  ├─ EraserTool.java        消しゴム（常に透明を書き込む）
│  ├─ FillTool.java          塗りつぶし（4方向）
│  ├─ EyedropperTool.java    スポイト
│  ├─ LineTool.java          直線（離すまでプレビューのみ、確定はEditorState経由）
│  ├─ SelectionTool.java     矩形選択（コピー/切り取り/削除/反転の対象範囲）

すべて既定パッケージ（package宣言なし）に置かれているため、`src` フォルダの中で
`javac *.java` → `java Main` だけでビルド・実行できます。新しいツールを追加する
場合は `Tool` インターフェースを実装して `EditorState` のツール一覧に登録するだけで
済むように設計しています。

### 現時点の制限事項

- レイヤー/フレームの**追加・削除自体はUndo対象外**です（ピクセルの描画・
  消しゴム・塗りつぶし・直線・貼り付け・反転はすべてUndo/Redo可能）
- オニオンスキンは**ひとつ前のフレームのみ**表示します（次のフレームは
  表示されません）
- 選択範囲は矩形のみです（自由形状選択には対応していません）
- パレットはプロジェクト保存でのみ保持されます（PNG単体の保存では失われます）
- コピー＆ペーストはアプリ内のみで完結します（OSのクリップボードとは連携しません）
- スマートフォン（iPhone/Android）には対応していません。Swing製のデスクトップ
  アプリはモバイルOS上でそのまま動作させることができないため、対応するには
  別プラットフォーム向けの作り直しが必要です

これらは今後の拡張余地として残しています。
